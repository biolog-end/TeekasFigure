# TeekasFigure

**GPU-ускоренная эволюционная аппроксимация изображений и видео с использованием геометрических фигур**

[🇬🇧 Read in English](README.md)

---

## Что такое TeekasFigure?

TeekasFigure воссоздаёт изображения и видео, последовательно накладывая геометрические фигуры (ваши кастомные PNG-текстуры) на холст с помощью эволюционного алгоритма. GPU (через WGPU/Vulkan/DX12) оценивает тысячи кандидатов параллельно, делая процесс невероятно быстрым и визуально впечатляющим.

Алгоритм эволюционирует популяцию фигур-кандидатов через турнирный отбор, мутацию и выживание сильнейших, создавая картины, напоминающие рисунки из геометрических мазков. В режиме видео алгоритм наделяет фигуры «памятью» и жизненным циклом, создавая плавные и завораживающие анимации.

### Ключевые возможности

- **Эволюционный алгоритм** — Турнирный отбор, мутации, многопоколенческое уточнение.
- **GPU-ускорение** — Compute-шейдеры оценивают тысячи кандидатов параллельно за доли секунды.
- **Кастомные фигуры** — Используйте любой PNG как кисть (круги, квадраты, брызги, листья, логотипы — что угодно!).
- **Продвинутая обработка видео (Temporal Coherence)** — Фигуры не просто перерисовываются каждый кадр. Они «живут» на холсте, адаптируясь под изменения (двигаются, поворачиваются, масштабируются), и умирают только при резкой смене сцены, освобождая место для новых.
- **Интерполяция кадров (Motion Blur эффект)** — Алгоритм умеет генерировать промежуточные кадры, делая анимацию невероятно плавной (фигуры плавно перетекают из одной точки в другую, новые фигуры мягко проявляются, а старые угасают).
- **Режим разнообразия фигур** — Не даёт алгоритму «лениться» и заставляет использовать весь арсенал ваших кистей.
- **Встроенный интерфейс настроек** — Настраивайте всё прямо в приложении (на русском или английском) с помощью умных слайдеров и переключателей, выбора файла и сохраняемых пресетов — без ручной правки `settings.toml`.
- **GIF процесса** — Опционально сохраняйте анимированный GIF процесса создания рядом с готовой картинкой.
- **Сохранение звука видео** — Оригинальная аудиодорожка видео сохраняется в итоговом MP4.
- **Глубокая настройка** — Управление всеми аспектами эволюции, жизни фигур и видео-пайплайна через интерфейс приложения и файл `settings.toml`.

### Требования

- **Rust** 1.70+ ([rustup.rs](https://rustup.rs/))
- **GPU** с поддержкой Vulkan, DX12 или Metal
- **FFmpeg** (необходим для работы с видео) — должен быть установлен и добавлен в PATH.

### Быстрый старт

```bash
# Клонировать репозиторий
git clone https://github.com/YOUR_USERNAME/TeekasFigure.git
cd TeekasFigure

# Собрать релиз (ОБЯЗАТЕЛЬНО для адекватной скорости)
cargo build --release

# Запустить
cargo run --release
```

### Как пользоваться

При запуске TeekasFigure открывается на **экране настроек** (одно окно, два экрана: Настройки → Генерация):

- **Язык** — переключение интерфейса между английским и русским (справа вверху). Выбор запоминается между запусками.
- **Входной файл** — выберите изображение/видео из `input_media/` в выпадающем списке (после добавления новых файлов нажмите *Обновить*).
- **Параметры** — каждая настройка это слайдер (по клику можно вписать точное число) или переключатель, сгруппированные в сворачиваемые секции. Неактуальные опции автоматически гаснут (серые) — например, параметры видео при выбранной картинке или подпараметры разнообразия, когда режим выключен.
- **Пресеты** — сохраните текущую конфигурацию под именем, загрузите её позже или удалите. Пресеты хранятся как `presets/*.toml`.
- **Сохранить settings.toml** — записывает текущую форму в `settings.toml` без запуска.
- **▶ Пуск** — проверяет настройки, сохраняет их в `settings.toml`, затем загружает медиа и фигуры и начинает генерацию.

При следующем запуске форма подтягивает начальные значения прямо из `settings.toml`.

### Структура папок

```text
TeekasFigure/
├── input_media/       ← Сюда кладёте целевое изображение (PNG/JPG/BMP) или видео (MP4)
├── raw_shapes/        ← Сюда складывайте ваши сырые картинки для фигур (кисти)
├── input_shapes/      ← Отсюда программа читает готовые текстуры (не кладите сырые файлы сюда!)
├── output/            ← Готовые работы (PNG, MP4 и опциональный _process.gif) сохраняются сюда
├── presets/           ← Сохранённые пресеты настроек (создаются из интерфейса)
├── settings.toml      ← Файл настроек (создаётся при первом запуске, обновляется из интерфейса)
└── TeekasFigure.exe   ← Скомпилированное приложение
```

### ⚠️ Подготовка кастомных фигур (Очень важно!)

**НЕ кладите свои картинки напрямую в папку `input_shapes/`!** Программа требует, чтобы фигуры были строго определённого формата (128x128, оттенки серого + сохранённый альфа-канал). Если подсунуть обычные PNG, алгоритм не сможет с ними работать.

Вместо этого положите свои картинки (PNG, JPG, BMP, WebP) в папку `raw_shapes/` и запустите встроенный скрипт:

```bash
cargo run --example prepare_shapes
```
Этот скрипт сам обрежет, перекрасит и переложит готовые оптимизированные текстуры в папку `input_shapes/`.

### Настройки (`settings.toml`)

Все параметры генерируются в файле `settings.toml` при первом запуске. Проще всего менять их через встроенный экран настроек, но можно править и сам файл. Для удобства они разбиты на логические группы:

#### ⚙️ Базовые настройки
| Параметр | Описание |
|----------|----------|
| **`batch_size`** | Количество кандидатов, генерируемых и оцениваемых за один проход на GPU (1–4096). |
| **`max_shapes`** | Максимальное количество фигур на холсте. В видео-режиме это целевой размер популяции. |
| **`mutations_per_frame`** | Сколько фигур успешно ставится за один отрисованный кадр интерфейса (влияет на скорость визуала). |
| **`max_texture_size`** | Максимальное разрешение, до которого будет сжато исходное медиа (для экономии ресурсов). |
| **`vram_budget_mb`** | Лимит видеопамяти для массива текстур фигур (в мегабайтах). |
| **`scale_min` / `scale_max`**| Минимальный и стартовый максимальный размер фигуры (масштаб адаптивно уменьшается по мере заполнения холста). |
| **`shape_resolution`** | Разрешение загружаемых фигур (по умолчанию 128, меняйте только если правили скрипт подготовки). |

#### 🎬 Настройки видео и анимации
| Параметр | Описание |
|----------|----------|
| **`target_fps`** | До скольки FPS сжать исходное видео перед обработкой. Итоговый FPS будет выше, если включена интерполяция. |
| **`scene_change_tolerance`**| Порог "смерти" фигуры (-10.0 до 10.0). Если фигура ухудшает картинку сильнее этого значения — она умирает и перерождается новой. **Отрицательные значения** заставляют тест быть строгим: фигура обязана *улучшать* свою зону, иначе умрёт. Меньше значение = более агрессивная перерисовка холста. |
| **`interpolation_steps`** | Количество плавно интерполированных кадров между ключевыми. `0` отключает. Если > 0, итоговое видео будет сверхплавным, а новые фигуры будут мягко проявляться (fade-in). Итоговый FPS = `target_fps * (steps + 1)`. |
| **`video_recolor`** | `false` (по умолчанию) — фигура навсегда запоминает свой первоначальный цвет. `true` — фигуры перекрашиваются под цвета нового кадра (может приводить к "выцветанию" деталей). |
| **`mutations_per_shape`** | Сколько попыток локального движения/масштабирования даётся фигуре для адаптации к новому кадру видео. |
| **`displacement_weight`** | Штраф за сильное смещение фигуры в видео (заставляет фигуры "держаться" за свои места, предотвращая хаотичное дрожание). |
| **`preserve_audio`** | Сохранять исходную аудиодорожку видео в итоговом MP4 (`true`, по умолчанию). Если в исходнике нет звука — ничего не происходит. |

#### 🎞️ GIF процесса (для изображений)
| Параметр | Описание |
|----------|----------|
| **`save_progress_gif`** | Сохранять анимированный GIF процесса создания рядом с готовой картинкой (`false` по умолчанию). Работает только для изображений — создаёт `<имя>_process.gif` в `output/`. |
| **`gif_fps`** | Скорость воспроизведения GIF в кадрах в секунду (1–50). |
| **`gif_frames`** | Примерное число захватываемых кадров, равномерно распределённых по процессу размещения фигур (2–2000). |
| **`gif_max_width`** | Максимальная ширина GIF в пикселях; большие холсты уменьшаются, чтобы файл оставался компактным (16–2048). |

#### 🧬 Параметры эволюции
| Параметр | Описание |
|----------|----------|
| **`evolve_opacity`** | Разрешить ли алгоритму подбирать прозрачность (`true`), или рисовать всегда полностью непрозрачными мазками (`false`). |
| **`use_original_colors`** | Использовать оригинальные цвета фигур (`true`) вместо тонирования grayscale-кистей (`false`, по умолчанию). При `true` фигуры берутся из папки **`raw_shapes/`** в их исходных RGB-цветах и НЕ перекрашиваются алгоритмом — только размещаются/двигаются/поворачиваются/масштабируются. Кладите цветные PNG (желательно с прозрачностью) в `raw_shapes/`. |
| **`evolve_non_uniform_scale`** | Разрешить независимое масштабирование по осям X и Y (`true`), чтобы фигуры могли растягиваться и сплющиваться (круг → эллипс, квадрат → прямоугольник). По умолчанию `false` — равномерный масштаб. |
| **`num_generations`** | Количество поколений эволюции (турниров и мутаций) для поиска идеальной фигуры. |
| **`min_improvement`** | Минимальный порог улучшения картинки (MSE) для принятия мазка на холст (отрицательное = улучшает). |
| **`use_min_improvement`** | Использовать ли порог `min_improvement`. **Важно: отключайте при использовании `diversity_mode`!** |
| **`max_rejections`** | Сколько раз подряд алгоритм должен провалить поиск хорошей фигуры, чтобы признать картину готовой. |
| **`survival_rate`** | Доля лучших фигур (например, 0.10 = 10%), выживающих для размножения в следующем поколении эволюции. |
| **`children_per_parent`** | Количество слегка изменённых (мутировавших) копий, создаваемых от каждой выжившей фигуры. |

#### 🎨 Режим разнообразия (Diversity Mode)
| Параметр | Описание |
|----------|----------|
| **`diversity_mode`** | Включает штрафы для слишком частых фигур, заставляя алгоритм использовать разные кисти. |
| **`diversity_penalty_increment`**| Штраф, который даётся фигуре каждый раз, когда она попадает на холст. |
| **`diversity_decay_enabled`**| Будут ли штрафы забываться со временем, позволяя снова использовать старые кисти. |
| **`diversity_decay_amount`** | На сколько снимается штраф с неиспользованных фигур при каждом шаге. |

> **🔥 ВАЖНО ПРО РЕЖИМ РАЗНООБРАЗИЯ (DIVERSITY MODE):**
> Штраф искусственно искажает математическую оценку "улучшения картинки". Поэтому **при включённом `diversity_mode = true` параметр `use_min_improvement` должен быть `false`**, иначе алгоритм начнёт отклонять все фигуры подряд из-за их штрафов и генерация остановится. Встроенный экран настроек делает это за вас автоматически (отключает `use_min_improvement`, пока включён режим разнообразия); при ручной правке `settings.toml` выставьте его сами.

### Управление в программе

Генерация начинается после нажатия **▶ Пуск** на экране настроек. Во время генерации:

| Клавиша | Действие |
|---------|----------|
| `Пробел` | Пауза / Продолжить генерацию |
| `S` | Моментально сохранить снимок (snapshot) текущего прогресса в папку `output/` |
| `Escape` | Экстренное завершение работы |
