# TeekasFigure

**GPU-ускоренная эволюционная аппроксимация изображений и видео с использованием геометрических фигур**
(Короче картинки из картинок)

[Read in English](README.md)

---

## Что такое TeekasFigure?

TeekasFigure воссоздаёт изображения и видео, последовательно накладывая геометрические фигуры (твои любые PNG-картинки) на холст с помощью эволюционного мега алгоритма. GPU (через WGPU/Vulkan/DX12) оценивает тысячи кандидатов параллельно, делая процесс невероятно быстрым и визуально крутым 😎.

Алгоритм эволюционирует популяцию фигур-кандидатов через турнирный отбор, мутацию и выживание сильнейших ✅. А в режиме видео алгоритм наделяет фигуры «памятью» и жизненным циклом, создавая плавные и абалденные анимации.

### Ключевые фишки

- **Эволюционный алгоритм** - Турнирный отбор, мутации, многопоколенческое уточнение, для лучшего экспиринтса
- **GPU-ускорение** - Compute-шейдеры оценивают тысячи кандидатов параллельно за доли секунды, видеокарта пашет, процессор отдыхает
- **Кастомные картинки** - Используйте любой PNG как кисть (фотографии из отпуска в анапе, любимые мемы, котиков, кадры bad apple, что угодно!).
- **Продвинутая обработка видео** - Фигуры не просто перерисовываются каждый кадр с нуля. Они «живут» на холсте, адаптируясь под изменения (двигаются, поворачиваются, масштабируются), и умирают только при резкой смене сцены, освобождая место для новых! Как настоящая волюция
- **Интерполяция кадров** - Мой свиток умеет генерировать промежуточные кадры, делая анимацию невероятно плавной (фигуры плавно перетекают из одной точки в другую, новые фигуры мягко проявляются, а старые угасают, иногда даже слишком плавно, но можно уменьшить число вычислений так).
- **Библиотеки картинок** - Образцы и картинки для сборки лежат в библиотеках с миниатюрами: добавляй, перетаскивай, удаляй и возвращай обратно.
- **Наборы из видео** - Нарезай кадры из любого ролика в набор кистей, можно сразу убрать фон (однотонный или нейросетью).
- **Адаптация палитры** - Подгоняет образец под цвета, которые реально есть у твоих цветных спрайтов.
- **Приоритет яркости** - Оценка по BT.709, где светотень и детали важнее точного оттенка.
- **Minecraft** - Экспортируй мобов как кисти, а потом смотри результат в игре, собранный из настоящих мобов.
- **Режим разнообразия фигур** - Работает не идеально, но не даёт алгоритму «лениться» и заставляет использовать больше арсенала ваших картинок.
- **Встроенный интерфейс настроек** - Красиви интерфейс, крути.
- **GIF процесса** - Опционально сохраняй анимированный GIF процесса создания рядом с готовой картинкой. Он правда не прям чтобы крутой.. Но вай нот?
- **Широкая поддержка форматов** - Изображения: PNG, JPG/JPEG, WebP, BMP, GIF (первый кадр), TIFF, TGA, ICO, QOI, PNM и другие. Видео: MP4, MOV, MKV, AVI, WebM, WMV, M4V, MPG/MPEG, TS, 3GP, OGV и другие. Но результат всегда сохраняется в MP4. Короче все типы файлов можно кидать
- **Глубокая настройка** - Управление всеми аспектами эволюции, жизни фигур и вообще всего! Когда много кнопочек, то программа кажется круче, вот я и сделала её круче.

### Требования

- **Rust** 1.80+ ([rustup.rs](https://rustup.rs/))
- **GPU** с поддержкой Vulkan, DX12 или Metal
- **FFmpeg** и **ffprobe** (нужны для работы с видео) — должны быть установлены и добавлены в PATH.
- **Windows SDK** с Resource Compiler (`rc.exe`) — для сборки Windows-версии с иконкой; готовому `.exe` SDK не нужен.
- По желанию: **Python** с `numpy` и `Pillow` для наборов из видео (и `onnxruntime` для удаления фона нейросетью)
- По желанию: **JDK 21**, чтобы собрать мод для Minecraft

## Как пользоваться

При запуске TeekasFigure открывается на **экране настроек**:

- **Язык** - (справа вверху). Всем понятно что это такое.
- **1. Что собираем** — библиотека образцов. Добавь файлы через **«+ Добавить фото / видео…»** и нажми на миниатюру нужного. Генерируется один выбранный образец. Кнопка «Обновить» перечитывает файлы, добавленные вне приложения.
- **2. Из каких картинок** — библиотека кистей. **«+ Добавить фотографии…»** копирует оригиналы и сама готовит чёрно-белые версии с сохранением прозрачности. В режиме исходных цветов используются цветные оригиналы.
- **Параметры** - каждая настройка это слайдер (по клику можно вписать точное число) или переключатель, сгруппированные в сворачиваемые секции. Неактуальные опции автоматически гаснут (серые) — например, параметры видео при выбранной картинке или подпараметры разнообразия, когда режим выключен, не дураки делали 😎
- **Пресеты** - сохрани текущую конфигурацию под именем, загрузите её позже или удалите. Чтобы не вносить вручную кучу настроек.
- **Сохранить settings.toml** - сохранить настройки без запуска генерации
- **▶ Пуск** - ну, вы понимаете

Кнопки добавления открывают **стандартный проводник Windows** с выбором нескольких файлов через Ctrl / Shift. Можно и просто перетащить файлы в окно — приложение спросит, куда их положить. Файлы с одинаковыми именами получают разные имена, внешние оригиналы не трогаются.

Чтобы удалить, отметь картинки под миниатюрами и нажми **«Удалить»**. Кисть удаляется вместе с её подготовленной копией. **«Отменить удаление»** возвращает последний набор, даже после перезапуска. Удалённое лежит в `.library_trash/` рядом с приложением, пока не почистишь вручную.

Диапазоны слайдеров — это рекомендации, а не жёсткие ограничения: вручную можно вписать больше, например 5 000 000 поколений. Значение вне диапазона подсвечивается оранжевым. Перед запуском приложение проверяет, хватит ли памяти видеокарты, RAM и места на диске, и если нет — честно об этом говорит.

На экране настроек видно, какая видеокарта используется. По умолчанию выбирается дискретная; если видеокарт несколько, можно выбрать нужную, сохранить и перезапустить.

### Во время генерации

Справа панель: прогресс, число фигур, отклонённые попытки, загрузка CPU/RAM/GPU и сколько кандидатов оценивается в секунду. Там же кнопки паузы, снимка и возврата к настройкам. **«Скрыть · H»** убирает панель и отдаёт всё окно холсту.

| Клавиша | Действие |
|---------|----------|
| `Пробел` | Пауза / Продолжить генерацию |
| `S` | Моментально сохранить снимок (snapshot) текущего прогресса в папку `output/` |
| `H` | Скрыть / показать панель |
| `Escape` | Остановить генерацию и вернуться к настройкам (на экране настроек — выход) |

Результаты сохраняются в `output/`: `<имя>_result.png` для картинок, `<имя>_result.mp4` для видео и по желанию `<имя>_process.gif`.

## Подготовка кастомных картинок

Используйте кнопку «+ Добавить фотографии…»: приложение скопирует оригиналы и подготовит чёрно-белые фигуры с сохранённой прозрачностью. Для повторной обработки имеющихся оригиналов есть **«Конвертация папки» → «Конвертировать в чёрно-белые фигуры»**: по умолчанию `raw_shapes/` → `input_shapes/`, с выбранным в настройках разрешением. Пропорции и исходный альфа-канал сохраняются.

Для командной строки есть `prepare_shapes.bat` и (всегда 128×128):

```bash
cargo run --release --example prepare_shapes -- raw_shapes input_shapes
```

## Набор картинок из любого видео

В разделе **«Из каких картинок»** нажмите **«Создать набор из видео…»**, выберите видео и укажите начало, конец и интервал снимков. Например: **с `2:00` до `3:00`, каждые `2` секунды** — примерно 30 картинок. Конечная отметка не включается; пустое поле «До» означает конец ролика. Можно ограничить размер кадра и выбрать обработку фона:

- **Сохранить фон** — весь кадр целиком.
- **Удалить однотонный фон** — убрать основной цвет, связанный с краями кадра. Подходит для силуэтов, например Bad Apple.
- **Выделить объект — ИИ (U²-Net)** — локальная нейросеть [U²-Net](https://github.com/xuebinqin/U-2-Net) через [ONNX Runtime](https://onnxruntime.ai/). Сложные сцены могут потребовать ручной доработки.

Можно обрезать прозрачные поля и пропускать одноцветные кадры. Новый набор выбирается сам и хранится в `frame_sets/<имя>/`. Флажок «Выбрать это же видео образцом для сборки» сразу выбирает этот ролик для генерации.

Для обработки фона нужен Python в PATH:

```bash
python -m pip install numpy Pillow onnxruntime
```

Модель ищется в `models/u2net.onnx` или `models/u2netp.onnx` рядом с EXE, затем в `U2NET_HOME`, затем в кэшах `.u2net/` и `.rembg/models/` в профиле пользователя. Ссылки на совместимые модели есть в [rembg](https://github.com/danielgatis/rembg). Приложение ничего не скачивает и не отправляет видео в сеть.

## Адаптация палитры

Если собирать картинку из цветных спрайтов, в результате могут быть только те цвета, которые у спрайтов есть. Выберите образец и набор спрайтов и нажмите **«Оптимизировать под выбранный набор»** под библиотекой образцов.

Программа соберёт палитру из видимых пикселей спрайтов и подготовит новый образец: мягко сгладит мелочи с сохранением границ, чуть добавит контраста, приглушит насыщенность и приблизит цвета к палитре (по желанию с дизерингом). В **«Параметрах адаптации палитры»** настраиваются сила каждого шага, число цветов (1–256) и размер ячейки дизеринга. Результат сохраняется новым файлом `_palette.png` / `_palette.mp4`, исходник не перезаписывается.

У видео одна палитра и один рисунок дизеринга на весь ролик, так что ничего не мерцает. Промежуточное видео пишется без потерь через `libx264rgb` — нужен FFmpeg с этим кодеком, и файлы получаются крупнее.

Если мелкий дизеринг портит результат — увеличьте ячейки, отключите смешивание или уменьшите силу. Тёмных/светлых оттенков, которых нет у спрайтов, адаптация не создаст.

## Приоритет яркости

**«Основное» → «Приоритет яркости (BT.709: яркость / цвет)»** меняет оценку кандидатов с обычной RGB-ошибки на взвешенную Y′CbCr. Светотень и детали становятся важнее точного оттенка. Работает во всех режимах фото и видео. Веса по умолчанию 6:1:1 (яркость : Cb : Cr), вес яркости можно менять.

<details>
<summary>Формула</summary>

`ошибка = 3 × (w·ΔY′² + ΔCb² + ΔCr²) / (w + 2)`, где
`Y′ = 0.2126R′ + 0.7152G′ + 0.0722B′`, `Cb = (B′ − Y′) / 1.8556`, `Cr = (R′ − Y′) / 1.5748`.

Коэффициенты из [BT.709](https://www.itu.int/rec/R-REC-BT.709). Нормировка держит ошибку в том же масштабе, что и RGB, поэтому пороги вроде `min_improvement` продолжают работать. Веса 6:1:1 — подобраны под эту задачу, а не какой-то стандарт зрения.

</details>

## 🍎 Bad Apple

Бонус для классического эффекта «Bad Apple!!»: собрать чёрно-белое видео с силуэтами из его **же** кадров. `prepare_bad_apple` берёт кадры из ролика, убирает однотонный фон, обводит каждый силуэт и сохраняет их как цветные кисти в `raw_shapes/`.

```bash
cargo run --release --example prepare_bad_apple -- "путь/к/ролику.mp4"
```

(или просто запусти `prepare_bad_apple.bat` и передай путь к видео)

| Опция | Описание |
|-------|----------|
| `--interval <сек>` | Секунд между кадрами (по умолчанию `2.0`). |
| `--out <папка>` | Куда сохранять PNG (по умолчанию `raw_shapes`). |
| `--max-size <px>` | Длинная сторона кисти в пикселях (по умолчанию `512`). |
| `--mono <0..1>` | Пропускать почти пустые кадры, где один цвет занимает ≥ эту долю (по умолчанию `0.97`). |
| `--bg-tol <0..255>` | Насколько цвет может отличаться от чисто белого/чёрного, чтобы считаться фоном (по умолчанию `40`). |
| `--outline <px>` | Толщина обводки цветом фона (по умолчанию `3`). |

Потом положи ролик в `input_media/`, включи `use_original_colors` и запускай.

## Видео из настоящих мобов Minecraft

Мод **TeekasFigure Mob Tools** (Fabric, Minecraft Java 1.21.1, Java 21, Fabric API не нужен) превращает результат в сцену из настоящих мобов.

1. **Сними кисти.** В одиночном мире Escape → **TeekasFigure: картинки мобов** → **Экспорт сверху** или **Экспорт лицом вперёд**. Мод отрисует каждого стандартного моба в прозрачный PNG 512×512.
2. **Импортируй.** В приложении **Minecraft / экспорт раскладки → Импортировать мобов из Minecraft…**, выбери папку с `mob_mapping.json`. Приложение создаст отдельную библиотеку и само выставит настройки: исходные цвета и экспорт сцены включены; HSV, прозрачность, растяжение, перекрашивание и затухание выключены. Для вида сверху поворот включён, для вида спереди — выключен.
3. **Сгенерируй** любую картинку или видео как обычно. В результате появится `output/scene_.../scene.json`.
4. **Смотри.** В игре открой **TeekasFigure: видео на мобах**, выбери `scene.json` и нажми старт. Мод соберёт картинку из настоящих мобов высоко над миром с ортографической камерой. **Остановить и вернуть** убирает сцену и возвращает игрока на место. Блоки мира не меняются.

Подробнее и про ограничения: [инструкция мода](minecraft/mob-exporter/README.md).

## Структура папок

```text
TeekasFigure/
├── input_media/       ← Сюда ложить целевое изображение или видео которое хотите
├── raw_shapes/        ← Сюда ложить сырые картинки из которых будет состоять целевое изображение
├── input_shapes/      ← Отсюда программа читает готовые картинки (вручную сюда ничего не ложить)
├── frame_sets/        ← Наборы картинок, нарезанные из видео
├── output/            ← Готовые работы сохраняются сюда
├── presets/           ← Сохранённые пресеты настроек (создаются из интерфейса)
├── settings.toml      ← Файл настроек (создаётся при первом запуске, обновляется из интерфейса)
└── TeekasFigure.exe   ← Скомпилированное приложение
```

## Настройки (`settings.toml`)

#### ⚙️ Базовые настройки
| Параметр | Описание |
|----------|----------|
| **`batch_size`** | Размер начальной популяции (слайдер 1–4096). GPU оценивает её порциями. |
| **`max_shapes`** | Максимальное количество фигур на холсте. В видео-режиме это целевой размер популяции. |
| **`mutations_per_frame`** | Целевое число размещений за цикл рабочего потока; интерфейс обновляется независимо. |
| **`max_texture_size`** | Максимальное разрешение, до которого будет сжато исходное медиа (для экономии ресурсов). |
| **`vram_budget_mb`** | Лимит видеопамяти для массива текстур фигур (в мегабайтах). |
| **`scale_min` / `scale_max`**| Минимальный и стартовый максимальный размер фигуры (масштаб адаптивно уменьшается по мере заполнения холста). |
| **`shape_resolution`** | Разрешение фигур и встроенной конвертации (по умолчанию 128). |
| **`perceptual_scoring`** | Оценка с приоритетом яркости (BT.709) вместо RGB (`false` по умолчанию). |
| **`luma_weight`** | Вес яркости для этой оценки (по умолчанию `6.0`). |

#### 🎬 Настройки видео и анимации
| Параметр | Описание |
|----------|----------|
| **`target_fps`** | До скольки FPS сжать исходное видео перед обработкой. Итоговый FPS будет выше, если включена интерполяция. |
| **`scene_change_tolerance`**| Порог "смерти" фигуры (-10.0 до 10.0). Если фигура ухудшает картинку сильнее этого значения — она умирает и перерождается новой. **Отрицательные значения** заставляют тест быть строгим: фигура обязана *улучшать* свою зону, иначе умрёт. Меньше значение = более агрессивная перерисовка холста. |
| **`interpolation_steps`** | Количество плавно интерполированных кадров между ключевыми. `0` отключает. Если > 0, итоговое видео будет сверхплавным, а новые фигуры будут мягко проявляться (fade-in). Итоговый FPS = `target_fps * (steps + 1)`. |
| **`video_recolor`** | `false` (по умолчанию) — фигура навсегда запоминает свой первоначальный цвет. `true` — фигуры перекрашиваются под цвета нового кадра (может приводить к "выцветанию" деталей). |
| **`mutations_per_shape`** | Сколько попыток локального движения/масштабирования даётся фигуре для адаптации к новому кадру видео (больше - лучше). |
| **`displacement_weight`** | Штраф за сильное смещение фигуры в видео (заставляет фигуры "держаться" за свои места, предотвращая хаотичное дрожание). |
| **`preserve_audio`** | Сохранять исходную аудиодорожку видео в итоговом MP4 (`true`, по умолчанию). Если в исходнике нет звука — ничего не происходит. |

#### 🎞️ GIF процесса (для изображений)
| Параметр | Описание |
|----------|----------|
| **`save_progress_gif`** | Сохранять анимированный GIF процесса создания рядом с готовой картинкой (`false` по умолчанию). Работает только для изображений — создаёт `<имя>_process.gif` в `output/`. |
| **`gif_fps`** | Скорость воспроизведения GIF в кадрах в секунду (1–50). |
| **`gif_frames`** | Примерное число захватываемых кадров, равномерно распределённых по процессу размещения фигур (2–2000). |
| **`gif_max_width`** | Максимальная ширина GIF в пикселях; большие холсты уменьшаются, чтобы файл оставался компактным (16–2048). |

#### 🧬 Параметры эволюции
| Параметр | Описание |
|----------|----------|
| **`evolve_opacity`** | Разрешить ли алгоритму подбирать прозрачность (`true`), или рисовать всегда полностью непрозрачными мазками (`false`). |
| **`evolve_rotation`** | Разрешить поворот фигур (`true` по умолчанию). При `false` поворот равен нулю и при создании, и при всех мутациях видео/эволюции. |
| **`export_scene`** | Сохранять текстуры и раскладку каждого итогового кадра в отдельный JSON-пакет (`false` по умолчанию). |
| **`use_original_colors`** | Использовать оригинальные цвета фигур (`true`) вместо тонирования чёрно-белых кистей (`false`, по умолчанию). При `true` фигуры НЕ перекрашиваются алгоритмом — только размещаются/двигаются/поворачиваются/масштабируются. |
| **`evolve_non_uniform_scale`** | Разрешить независимое масштабирование по осям X и Y (`true`), чтобы фигуры могли растягиваться и сплющиваться (круг → эллипс, квадрат → прямоугольник). По умолчанию `false` — равномерный масштаб. |
| **`evolve_hue`** | Только в режиме реального цвета (`use_original_colors = true`). Эволюция **оттенка** (hue) оригинальных цветов фигуры (`true`): каждая фигура может крутить цвет по цветовому колесу, чтобы точнее попасть в цель. По умолчанию `false`. |
| **`evolve_saturation`** | Только в режиме реального цвета (`use_original_colors = true`). Эволюция **насыщенности** (saturation) оригинальных цветов фигуры (`true`): фигура может становиться более/менее яркой ради точного совпадения с целью. По умолчанию `false`. |
| **`evolve_brightness`** | Только в режиме реального цвета (`use_original_colors = true`). Эволюция **яркости** (value/brightness) оригинальных цветов фигуры (`true`): фигура может затемняться или осветляться. По умолчанию `false`. |
| **`num_generations`** | Количество поколений эволюции (турниров и мутаций) для поиска идеальной фигуры. |
| **`min_improvement`** | Порог принятия мазка по изменению ошибки (отрицательное = улучшает). |
| **`use_min_improvement`** | Использовать ли порог `min_improvement`. **Важно: отключайте при использовании `diversity_mode`!** |
| **`max_rejections`** | Сколько раз подряд алгоритм должен провалить поиск хорошей фигуры, чтобы признать картину готовой. |
| **`survival_rate`** | Доля лучших фигур (например, 0.10 = 10%), выживающих для размножения в следующем поколении эволюции. |
| **`children_per_parent`** | Количество слегка изменённых (мутировавших) копий, создаваемых от каждой выжившей фигуры. |

#### 🎨 Режим разнообразия (Diversity Mode)
| Параметр | Описание |
|----------|----------|
| **`diversity_mode`** | Включает штрафы для слишком частых фигур, заставляя алгоритм использовать разные кисти. |
| **`diversity_penalty_increment`**| Штраф, который даётся фигуре каждый раз, когда она попадает на холст. |
| **`diversity_decay_enabled`**| Будут ли штрафы забываться со временем, позволяя снова использовать старые кисти. |
| **`diversity_decay_amount`** | На сколько снимается штраф с неиспользованных фигур при каждом шаге. |

> **🔥 ВАЖНО ПРО РЕЖИМ РАЗНООБРАЗИЯ (DIVERSITY MODE):**
> Штраф искусственно искажает математическую оценку "улучшения картинки". Поэтому **при включённом `diversity_mode = true` параметр `use_min_improvement` должен быть `false`**, иначе алгоритм начнёт отклонять все фигуры подряд из-за их штрафов и генерация остановится. Встроенный экран настроек делает это за вас автоматически (отключает `use_min_improvement`, пока включён режим разнообразия); при ручной правке `settings.toml` выставьте его сами.
